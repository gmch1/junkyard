用于保存独立、轻量、可复用的小工具。仓库里的每个一级子目录都是一个独立项目，拥有自己的源码、构建入口、使用说明和 CI/CD。

## 新增项目约定

每次加入新的零碎项目时：

1. 在仓库根目录创建一个语义清晰、使用小写连字符命名的独立目录；
2. 项目源码、配置和构建脚本全部放入该目录，不与其他项目互相依赖；
3. 为项目编写独立 `README.md`，至少说明用途、要求、安装、配置、验证和安全边界；
4. 在本文件的“项目索引”中新增一行；
5. 在 `.github/workflows/` 增加或扩展路径过滤的 CI；
6. 忽略缓存、密钥、依赖目录和本地构建产物；
7. 本地验证通过后再提交。

## CI/CD原则

- 工作流应使用 `paths` 限定到对应项目，避免无关项目重复构建；
- Pull Request 和默认分支推送至少执行构建或测试；
- 可分发项目应上传构建产物；
- 发布标签应包含项目名称，避免多个子项目版本冲突；
- 仓库中不得提交证书、私钥、密码或其他凭证。
